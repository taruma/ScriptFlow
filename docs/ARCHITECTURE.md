# Architecture — Auteur Script Editor

## 1. Plain-Text-as-Truth Data Flow

The editor treats the **canonical plain-text Auteur Script** as the single source of truth so Live Mode, Source Mode, clipboard exports, and `localStorage` persistence can never drift out of sync:

```text
                       ┌────────────────────────────────────┐
                       │  history.present: rawText (Truth)  │
                       │  (src/core/history.ts)             │
                       │  + useEditorSettings() (Display)   │
                       └─────────────────┬──────────────────┘
                                         │
              ┌──────────────────────────┼──────────────────────────┐
              ▼                          ▼                          ▼
   [ Pure Synchronous Pipeline ]   [ Pure UI Mutations ]   [ Programmatic JSON Engine ]
   1. parseAuteurScript(raw)       (src/core/serializer)   (src/core/ir, patch, slicer)
   2. extractMetadata(doc)         • insert/update/delete  • toAuteurIR / fromAuteurIR
   3. lintDocument(doc, meta, rules)  & reorder Staging     • toAuteurEnvelope / Draft
   4. tokenize* (highlighter)      • insert/update/delete  • applyAuteurPatch (tx+lint)
   5. parseAestheticRows             ExecutionBeat/Sub…    • sliceAuteurEnvelope (L1–L5)
                                   • reorderExecutionBeats • getAuteurJsonSchemas (Zod)
                                   • exportTagless
              │                          ▲                          ▲
              ▼                          │                          │
   [ Thin React + Tailwind UI (src/components/) ] ────────┘   [ AI / Automated Callers ]
   • ErrorBoundary -> App              • TopSlateBar -> FileMenuDropdown / SettingsPopover
   • LiveDocument -> StagingPane / ExecutionPane (SortableList + HoverInsertSeam)
   • StagingBlockCard -> Registry      • ExecutionBeatRow       • SourceEditor
   • LiveHighlightedEditor             • ScriptLibraryModal     • ConfirmDialog / DiagnosticDot
```

## 3. Pure Serializer Mutation Contracts

Every mutation function in `src/core/serializer.ts` obeys three invariants:
1. **Immutability**: Takes `(raw: string, ...args)` and returns a new canonical `string` without mutating inputs.
2. **Block Orthogonality**: Inserting (`insertStagingBlock`), editing (`updateStagingBlock`), deleting (`deleteStagingBlock`), or reordering (`reorderStagingBlocks`) a Staging Macro-Block preserves every other Staging Macro-Block and all Execution Macro-States untouched; editing, inserting, deleting, or reordering Execution Macro-States never alters Staging Macro-Blocks. `insertStagingBlock` also rejects reserved Execution headers (`EXECUTION`, `TIMELINE`, `BEATS`, `SHOTLIST`).
3. **Single-Line Macro-State Guarantee**: `updateExecutionBeat` and `insertExecutionBeat` normalize accidental internal newlines into single spaces so each Macro-State remains one clean line inside `[EXECUTION]`.

## 4. Global Document Guards (Paste-and-Hydrate & Undo/Redo)

In `src/App.tsx`, two document-level listeners coordinate frictionless script ingestion and history navigation without colliding with active inline inputs or open modals:

### Paste-and-Hydrate Guard
Uses `isMultiBlockAuteurScript()` from `src/core/parser.ts`:
- **Modals & AI Sidebar (`isDebugOpen`, `isLibraryOpen`, `confirmRequest`, `[aria-modal="true"]`, or `[data-ai-sidebar="true"]`)**: Ignored so modal inputs (including `AiSettingsModal` API key entry) and AI chat composer pastes never trigger script hydration.
- **Read-only bundled examples**: Intercepts document-level pastes without mutating the read-only example and displays a gentle toast guiding the user to click **Fork to Edit** or create a **New Blank Script**.
- **Pasting outside any focused input/textarea (custom script)**: Immediately replaces `rawText` in place (as an undoable `'checkpoint'` history entry), parses the script, switches to Live Mode, and displays a subtle toast.
- **Pasting a multi-block Auteur Script (2+ canonical Macro-Block headers)** while inside a focused single Macro-Block or Macro-State editor in Live Mode: Blurs the active field and hydrates the entire script.
- **Pasting a normal inline snippet** while focused inside a Staging Macro-Block, Execution Macro-State, Scene Title, or Source Mode editor: Passes through natively without interception.

### Document-Level Undo / Redo Guard
Uses `matchHistoryShortcut()` (`src/ui/historyShortcuts.ts`) and `src/core/history.ts`:
- **Commit Modes & Lifecycle Reset**: Rapid typing commits with `mode: 'coalesce'` + a scoped `groupKey` (auto-checkpointing on bulk edits > 32 chars or pauses > 800ms); structural actions (splits, merges, inserts, deletes, reorders, paste-hydrate, AI suggestion applies, debug commits) commit with `mode: 'checkpoint'`. Switching scripts, forking an example, importing a script, or creating a blank script resets history cleanly via `createDocumentHistory()` (while **Fork & Apply** from the AI sidebar initializes the forked script's history from the example base with the AI edit committed as a single undoable checkpoint).
- **Read-Only, Modal & Native-Input Isolation**: Skips shortcuts when viewing a read-only bundled example, whenever a modal is open (`isDebugOpen`, `isLibraryOpen`, `confirmRequest`, or any `[aria-modal="true"]` element), or when focus sits inside a `[data-native-undo="true"]` input (Scene Title, custom Staging header field, Library search/rename inputs, AI chat composer, and AI Settings API key input).
- **Active-Draft Resync**: Stepping Undo/Redo increments `history.revision`, prompting memoized Live Mode editors (`StagingBlockCard`, `AestheticBlockEditor`, `ExecutionBeatRow`) to immediately resync their local drafts even while focused.

### Multi-Script Persistence & Crash-Recovery Mirror (`src/ui/useScriptLibrary.ts`)
- **Mount Hydration**: On mount, `useScriptLibrary` runs `scriptLibraryDb.migrateFromLegacyLocalStorage()`, loads the IndexedDB library list, and opens the active custom script or bundled example (falling back to `DEFAULT_PRESET`).
- **Debounced IndexedDB Save + Tab-Hide/Reload Flush + `localStorage` Mirror**: Edits and title renames on custom scripts debounce-save (`350ms`) to `scriptLibraryDb.put()` and flush immediately on `visibilitychange` (when `document.visibilityState === 'hidden'`), `pagehide`, script switches, backups, or unmount while continuously calling `mirrorActiveScriptToLocalStorage()` so `ErrorBoundary` crash recovery stays intact. Bundled examples remain strictly read-only and never auto-create IndexedDB records until the user explicitly clicks **Fork to Edit** in `TopSlateBar` (or **Fork** in the Library).

## 5. Programmatic JSON IR, Patch & Lens Slicer Layer

To support model-agnostic **Create**, **Edit**, and **Evaluate** pipelines without breaking **Plain-Text-as-Truth**, `src/core/` exposes a pure TypeScript + Zod programmatic interchange layer (fully specified in `docs/JSON_IR_SPEC.md`) with optional `ruleOverrides?: LintRuleOverrides` support across `toAuteurEnvelope()`, `compileAuteurDraft()`, `applyAuteurPatch()`, and `sliceAuteurScript()`:

- **Create**: `compileAuteurDraft(input, ruleOverrides?)` validates untrusted JSON drafts against `AuteurScriptDraftSchema`, compiles deterministically to canonical `v0.4.0` plain text via `fromAuteurIR()`, and returns Script Supervisor diagnostics.
- **Edit**: `applyAuteurPatch(rawText, patch, options)` executes multi-op batches transactionally against snapshot-stable IDs (`MB#`, `MB#.#`, `S#`, `S#.#`) with optional `expectedSnapshotHash` concurrency checks, `ruleOverrides`, and a `rejectOnNewErrors` deterministic lint gate. `projectAuteurPatchPreview(rawText, patch)` reuses the same origin-tracked working IR loop purely (zero mutations) to map pre-patch Staging Macro-Block indices (`MB#`), Execution Macro-State indices (`S#`), and insertion seams to exact before/after text even across multi-op batches with inserts, deletes, and reorders.
- **Evaluate**: `sliceAuteurEnvelope()` / `sliceAuteurScript(rawText, specOrPreset, ruleOverrides?)` isolate arbitrary dimensions (plus 5 built-in `AUDIT_LENS_PRESETS`) paired with deterministically inherited `resolvedCamera.effectiveFraming`, and `validateAuteurReview()` validates structured findings with executable `suggestedPatch` payloads.

## 6. AI Service, Knowledge Registry & Unified Tool Runtime (`src/services/`)

All model-specific orchestration, craft knowledge composition, and external SDK usage live strictly inside `src/services/` (with browser BYOK preferences in `src/ui/aiSettings.ts`), preserving `src/core/` as 100% pure, platform- and model-agnostic TypeScript:

- **BYOK Configuration (`src/ui/aiSettings.ts`)**: Stores Gemini 4 model selection (`gemini-4-hydrogen`, `gemini-4-argon`, `gemini-4-carbon`), reasoning level (`low` / `medium` / `high`), `showThinkingSummary`, and opt-in `showDebugTrace` (default `false`) in `localStorage`. Stores the user's BYOK API key in `localStorage` by default or moves it cleanly into tab-scoped `sessionStorage` when `sessionOnly` is toggled on, with `clearApiKey()` purging both stores.
- **Browser-Local Craft & Skills Store (`src/ui/aiSkillsStore.ts`)**: Persists user overrides for `foundationalCraftOverride`, per-skill `skillOverrides` (`auto | pinned | muted`, `bodyOverride`), custom Extension Skills (`customSkills`), and `knowledgeVersion` in `localStorage` (`auteur-editor-ai-skills-v1`) via `useAiSkills()`. Pure helpers enforce `snake_case` custom skill IDs, block collisions with built-in skill IDs (`slugifyCustomSkillId`, `validateCustomSkillInput`), and detect upstream knowledge updates (`hasUpstreamKnowledgeUpdate`) when built-in defaults evolve while overrides exist.
- **Auteur Craft Knowledge & Context Composer (`src/services/auteurKnowledge.ts`)**: Pure TypeScript (zero React/DOM/`localStorage`) SSOT for platform-agnostic `v0.4.0` craft instructions (`AUTEUR_KNOWLEDGE_VERSION`, `DEFAULT_FOUNDATIONAL_CRAFT`), code-owned read-only tool protocol (`buildToolProtocolBlock`), 6 built-in extension skills (`BUILTIN_AUTEUR_SKILLS`: `draft_craft` with curated examples from `BUNDLED_EXAMPLES`, `video_continuation`, `token_mapping`, `character_reference`, `temporal_calibration`, `spatial_fences`), and topology-filtered 5-lens audit checklists (`getLensAuditChecklist`, suppressing cross-cut 180°/carryover/wear/prop checks on `discontinuous_montage`). `composeAgentContext()` runs `toAuteurEnvelope()` once per turn to inject a compact Live Editor State summary (`snapshotHash`, `changedSinceLastTurn`, topology, active deterministic lint) and optional mode-agnostic `sceneBrief` reference context (`briefContext`), resolves every built-in and custom skill into strictly one mutually exclusive state (`active | available | muted`) via passive triggers (including active `referenceHandles` from the Brief modal so `@video*` activates `video_continuation` and `@image*`/`@actor*`/`@audio*` activates `character_reference` across all modes) and `auto | pinned | muted` overrides, and computes editor-state-aware `allowedToolNames` across unified `AssistantFocus` (`'auto' | 'draft' | 'refine' | 'audit'`, mapped cleanly from legacy `AssistantMode` via `assistantModeToFocus()`).
- **Focus- & Context-Scoped Local Script Tools (`src/services/scriptTools.ts`)**: Exposes strictly read-only/staging browser tools backed by `src/core/` (`get_script_overview`, `inspect_lens_slice` with co-located topology-filtered `checklist` for built-in presets, `propose_script_patch`, `propose_script_draft`, `report_audit_review`, and dynamic `load_auteur_skill`). Heavy static Zod-derived tool schemas stay cached, while `buildToolDeclarationsForContext()` builds `load_auteur_skill`'s schema dynamically per turn from `context.availableSkills` (including custom user skills) and passes all declarations through `sanitizeJsonSchemaForTool()`. `executeScriptToolCall()` enforces the turn's resolved `allowedTools` and the `active | available | muted` skill state machine (returning `alreadyActive: true` for active skills and rejecting muted/unknown skills), dry-runs edits against active `ruleOverrides`, and stages reviewable suggestions (`PatchSuggestion`, `DraftSuggestion`, `AuditReviewSuggestion`) without ever mutating `rawText` directly. Also exports pure Audit Review composition helpers (`rebaseAuditReviewAfterFix()` to safely rebase provably non-conflicting sibling fixes onto the updated script after applying one fix, and `composeAuditFixesBatch()` to greedily combine compatible unapplied fixes into a single transactional Undo checkpoint). Legacy `MODE_TOOL_NAMES`, `getToolDeclarationsForMode()`, and `getSystemInstructionForMode()` remain intact for backwards compatibility.
- **Streaming Interactions Client & Sanitized Trace Capture (`src/services/geminiInteractions.ts`)**: Uses `@google/genai` (`ai.interactions.create`) with `stream: true`, composing context once per turn via `composeAgentContext()` (forwarding `focus`, `previousSnapshotHash`, overrides, `customSkills`, `referenceHandles`, and `briefContext`) and `buildToolDeclarationsForContext()`, chaining multi-turn server state via `previous_interaction_id`, and re-specifying `tools`, `system_instruction`, and `generation_config: { thinking_level, thinking_summaries: 'auto' }` on every call. Captures a sanitized `AgentTurnTrace` (including `mode`, `focus`, `activeSkillIds`, `loadedSkillIds`, aggregated `usage`, normalized `error`, and per-round `rounds`) returned on `RunAgentTurnResult` and attached onto `GeminiServiceError` on failure/abort—strictly excluding `apiKey` and auth headers and redacting any echoed secret.
